## Цель

Довести Security Rules от каркаса шага 8 (`users`/`profiles` + default deny) до полного
покрытия **всех** коллекций Сессии 2 с проверкой роли, владельца и членства в группе, и
настроить Storage Rules для безопасной загрузки файлов. Безопасность держится на сервере, а
не на скрытии кнопок (ТЗ §8.1). Соответствие ТЗ §8 (§8.2–8.6), §16.6.

## Действия

1. **Переключить `getRole()` на custom claims** (`request.auth.token.role`), которые
   проставляет Cloud Function из шага 10 — вместо `get(/users/$(uid))` на каждый запрос; это
   убирает лишние чтения (ТЗ §10) и ускоряет проверки. Каркас шага 8 явно это предусматривал.
2. **Хелперы доступа** (расширить `firestore.rules`, шаг 8): к `isSignedIn/isAdmin/isTeacher/
   isStudent/isOwner` добавить `isCourseOwner(courseId)`, `isGroupMember(groupId)`,
   `isCourseStudent(courseId)`, `isVerified()` — членство/владение через поля документов или
   claims, без тяжёлых обходов.
3. **Правила по каждой коллекции** (ТЗ §8.2–8.3): per-collection `read`/`write` для `roles`,
   `groups`, `courses`, `courseWeeks`, `materials`, `assignments`, `submissions`, `grades`,
   `questionBank`, `quizzes`, `quizAttempts`, `notifications`, `auditLogs`, `systemSettings`,
   `inviteCodes`, summary-документов (шаг 25) — см. матрицу ниже.
4. **Защита данных** (ТЗ §8.3): запрет чтения чужих оценок и попыток; студент не меняет оценку
   и правильные ответы; скрытые материалы (`isPublished == false`) не видны студенту; проверка
   владельца курса перед редактированием; проверка членства в группе перед доступом к курсу.
5. **Защита квизов** (ТЗ §8.5): правильные ответы недоступны студенту до завершения попытки;
   `quizAttempts` неизменяемы после `finishedAt`; расчёт баллов и проверка дедлайна — сервером
   (шаг 24), правила запрещают студенту писать `score`.
6. **Журнал** (ТЗ §8.6): `auditLogs` доступен на чтение только админу, на запись — только Cloud
   Functions (с клиента запись запрещена); `systemSettings` — чтение по необходимости, запись
   только админ/сервер.
7. **Storage Rules** (ТЗ §8.4, `storage.rules` от каркаса шага 8): лимит размера файла,
   whitelist безопасных типов, запрет исполняемых; студент грузит файлы только в свои
   `submissions`; преподаватель читает файлы только своих курсов; админ — в рамках
   администрирования; привязка файла к пользователю и сущности по пути.
8. **Default deny** сохраняется: всё неуказанное — запрещено (как в каркасе шага 8).
9. **Unit-тесты правил** (расширить `test/security/` из шага 8, `@firebase/rules-unit-testing`,
   ТЗ §16.6): по каждой коллекции — студент не лезет в чужие оценки/попытки, не меняет
   правильные ответы и оценки, не видит скрытое; преподаватель ограничен своими курсами/
   группами; админ видит всё; запись в `auditLogs`/summary с клиента запрещена.

| Коллекция | read | write |

| `users` | владелец, админ | create — владелец (роль `student`); update/delete — админ/CF |
| `profiles` | авторизованные | владелец, админ |
| `roles` | админ | только CF/админ |
| `groups` | члены группы, её преподаватели, админ | преподаватель-владелец, админ |
| `courses` | назначенные студенты, преподаватель курса, админ | преподаватель-владелец, админ |
| `courseWeeks` | студенты курса (опубликованные), преподаватель курса, админ | преподаватель курса, админ |
| `materials` | студенты курса (если `isPublished`), преподаватель курса, админ | преподаватель курса, админ |
| `assignments` | студенты курса (опубликованные), преподаватель курса, админ | преподаватель курса, админ |
| `submissions` | автор-студент, преподаватель курса, админ | автор-студент (своя, до дедлайна); статус/оценку — преподаватель |
| `grades` | студент-владелец (read), преподаватель курса, админ | преподаватель курса, админ/CF (студент — нет) |
| `questionBank` | преподаватель-владелец, админ | преподаватель-владелец, админ (студент — нет) |
| `quizzes` | студенты курса (без правильных ответов), преподаватель курса, админ | преподаватель курса, админ |
| `quizAttempts` | автор-студент, преподаватель курса, админ | создание — студент; `score`/итог — только CF; неизменяемы после `finishedAt` |
| `notifications` | адресат-владелец | только CF (создание/рассылка) |
| `auditLogs` | админ | только CF (запись), клиент — запрещено |
| `systemSettings` | по необходимости (чтение) | админ, CF |
| `inviteCodes` | преподаватель-владелец, админ | преподаватель-владелец, админ; проверка — CF |
| summary-документы (шаг 25) | владелец/преподаватель/админ по области | только CF (пересчёт), клиент — read-only |

## Storage rules

```
rules_version = '2';

// ТЗ §8.4: лимит размера, безопасные типы, запрет исполняемых,
// привязка файла к пользователю и сущности. Default deny на всё остальное.
service firebase.storage {
  match /b/{bucket}/o {

    function isSignedIn() { return request.auth != null; }
    function role()       { return request.auth.token.role; } // custom claim (шаг 10)

    // Общие ограничения загрузки (§8.4 п. 4–6).
    function withinSize()  { return request.resource.size < 25 * 1024 * 1024; }
    function safeType()    { return request.resource.contentType.matches(
                               'image/.*|application/pdf|application/zip|text/plain|' +
                               'application/vnd.openxmlformats-officedocument.*'); }
    function notExecutable() { return !request.resource.contentType.matches(
                               '.*(x-msdownload|x-sh|x-executable|x-msdos-program).*'); }

    // Аватары: владелец пишет свой, читают авторизованные.
    match /avatars/{uid}/{file} {
      allow read:  if isSignedIn();
      allow write: if request.auth.uid == uid && withinSize() && safeType() && notExecutable();
    }

    // Материалы курса: пишет преподаватель/админ, читают участники курса.
    match /courses/{courseId}/materials/{file} {
      allow read:  if isSignedIn();
      allow write: if role() in ['teacher', 'admin']
                   && withinSize() && safeType() && notExecutable();
    }

    // Отправки заданий: студент грузит только в свои submissions (§8.4 п. 1);
    // преподаватель/админ только читают (§8.4 п. 2–3).
    match /submissions/{courseId}/{uid}/{file} {
      allow read:  if request.auth.uid == uid || role() in ['teacher', 'admin'];
      allow write: if request.auth.uid == uid
                   && withinSize() && safeType() && notExecutable();
    }

    // Всё остальное — запрещено (default deny).
    match /{allPaths=**} {
      allow read, write: if false;
    }
  }
}
```

> Точные проверки владения курсом/группой в путях Storage опираются на custom claims и
> структуру путей; контрольная привязка владельца к сущности дублируется в Firestore-правилах.

## Решения

- **Custom claims вместо `get()` в `getRole()`** — устраняет чтение `users` на каждый запрос
  правил (ТЗ §10), ускоряет проверки; роль синхронизирует CF (шаг 10).
- **Per-collection правила с проверкой роли + владельца + членства** — реализуют §8.2
  (разграничение) и §8.3 (защита данных) на сервере, а не в UI (§8.1).
- **Неизменяемость `quizAttempts` после `finishedAt` и запрет записи `score` студентом**
  (§8.5) — результат нельзя подменить с клиента, дополняет серверный расчёт шага 24.
- **`auditLogs` и summary — write только CF** (§8.6, шаг 25) — клиент не подделывает журнал и
  агрегаты; чтение журнала — только админ.
- **Storage: whitelist типов + лимит размера + запрет исполняемых** (§8.4) — белый список
  безопаснее чёрного; путь кодирует владельца и сущность (привязка §8.4 п. 7).
- **Default deny остаётся базой** — новые коллекции закрыты, пока не описаны явно (наследие
  каркаса шага 8).

## Артефакты

расширенный `firestore.rules` (хелперы владения/членства, правила всех коллекций, claims),
расширенный `storage.rules` (лимиты/типы/владение, default deny),
`firestore.indexes.json` (при необходимости для правил-зависимых запросов),
`test/security/firestore_rules.test.mjs` (тесты по каждой коллекции — расширение шага 8),
`test/security/storage_rules.test.mjs` (тесты загрузки: размер/тип/владение).

## Готово, когда

Правила покрывают все коллекции шагов 10–26 с проверкой роли/владельца/членства; студент не
читает чужие оценки и попытки, не меняет оценки и правильные ответы, не видит скрытое (§8.3);
квизы защищены (§8.5); `auditLogs` и summary недоступны на запись с клиента (§8.6, шаг 25);
Storage ограничивает размер/типы, запрещает исполняемые и пускает студента только в свои
submissions (§8.4); `getRole()` работает через custom claims; default deny сохранён; unit-тесты
правил (Firestore + Storage) на эмуляторе зелёные (§16.6); `dart analyze` чисто.
