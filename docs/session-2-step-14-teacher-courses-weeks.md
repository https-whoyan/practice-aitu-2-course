## Цель

Преподаватель управляет своими курсами и учебными неделями: создаёт и редактирует курс,
строит структуру недель (порядок, публикация/скрытие), дублирует курс и делает копию на новый
учебный период. Используются доменные репозитории из шага 13 под teacher-shell'ом навигации
(шаг 9). Соответствие ТЗ §5.4.1, §5.4.3, §5.4.4, §14.3, §17.2.

## Действия

1. **Экран «Мои курсы»** — список курсов преподавателя через
   `watchCoursesByOwner(currentUid)` (шаг 13), карточки со статусом и кнопкой «Создать курс»;
   пустое состояние `AppEmptyView` (шаг 5). Заменяет заглушку раздела (шаг 9).
2. **Создание/редактирование курса** — форма (название, описание, обложка, назначение групп,
   статус черновик/активный/архивный) поверх `CourseRepository.createCourse/updateCourse`
   (шаг 13); обложка грузится в Storage (`firebaseStorageProvider`, шаг 2; правила — шаг 27).
3. **Страница курса** — вкладки/секции: недели, материалы (шаг 15), задания (шаг 17), статистика
   (шаг 25, заглушка). Шапка с названием/статусом и действиями курса.
4. **Управление неделями** (ТЗ §5.4.4) — список недель по `orderIndex`: добавить, редактировать
   (название/описание/даты), удалить, **менять порядок** (drag/`reorderWeeks`),
   **публиковать/скрывать** (`setPublished`) — через `CourseWeekRepository` (шаг 13).
5. **Дублирование курса и копия на новый период** (ТЗ §5.4.3) — `duplicateCourse` /
   `copyToNewPeriod` (шаг 13): копируются недели и материалы, статус нового курса — черновик.
6. **Проверка владельца** — действия редактирования доступны при `ownerTeacherId == currentUid`
   (или входит в `teacherIds`); UI прячет недоступное, реальная граница — Security Rules
   (шаг 27, ТЗ §8.1, §8.3 п.7).
7. **Riverpod-контроллеры** (`@riverpod`, шаг 4) для форм и операций; ошибки → `Failure` →
   `AppErrorView` (шаг 5).

## Экраны (ТЗ §14.3)

| Маршрут | Экран | Назначение |
|---------|-------|------------|
| `/teacher/courses` | Мои курсы | Список курсов преподавателя, вход в создание |
| `/teacher/courses/new` | Создание курса | Название, описание, обложка, группы, статус |
| `/teacher/courses/:id/edit` | Редактирование курса | Правка полей и назначений курса |
| `/teacher/courses/:id` | Страница курса | Недели, материалы, задания, статистика |
| `/teacher/courses/:id/weeks` | Управление неделями | Список недель, порядок, публикация |
| `/teacher/courses/:id/weeks/new` | Создание недели | Номер, название, описание, даты |
| `/teacher/courses/:id/weeks/:weekId/edit` | Редактирование недели | Правка недели, публикация/скрытие |

> Маршруты — под teacher-`StatefulShellRoute` (шаг 9); заглушки раздела «Мои курсы»
> заменяются этими экранами без переделки навигации.

## Решения

- **Маршруты под ролевым teacher-shell'ом** (шаг 9) — навигация курса живёт внутри своей
  вкладки, состояние стека сохраняется.
- **Формы поверх репозиториев шага 13**, без прямого доступа к Firestore — единый эталон
  (шаг 4/6); валидация на клиенте + сервер (ТЗ §8.3 п.9).
- **Управление порядком недель через `orderIndex`** (drag-and-drop) — переупорядочивание не
  трогает остальные поля недели.
- **Публикация/скрытие недели — переключатель `isPublished`** на странице недели; студент
  скрытые не видит (шаг 16 + правила шага 27, ТЗ §5.4.4 п.10–11).
- **Дублирование/копия на период — серверно-консистентно** (batch или Cloud Function),
  чтобы недели и материалы копировались атомарно (ТЗ §5.4.3 п.9–10).
- **Проверка владельца `ownerTeacherId`** дублируется в правилах — клиентский guard лишь UX
  (ТЗ §8.1).

## Готово, когда

Преподаватель видит свои курсы, создаёт/редактирует курс, открывает страницу курса; добавляет
недели, меняет их порядок, публикует и скрывает; дублирует курс и делает копию на новый период;
чужой курс не редактируется (guard + правила); сценарий ТЗ §17.2 проходит на эмуляторе;
`dart analyze` чисто.
