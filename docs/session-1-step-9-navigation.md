# Сессия 1 · Шаг 9 — Скелет навигации и dashboard'ы

Детализация шага 9 из [`session-1-foundation.md`](session-1-foundation.md), блок C (Навигация-скелет).

> Формат: **Цель** · **Действия** · **Разделы по ролям** · **Решения** · **Артефакты** · **Готово, когда**.

---

## Цель

Адаптивная навигационная оболочка (sidebar на web, bottom nav на mobile), пустые
экраны-заглушки всех основных разделов и три ролевых dashboard'а без данных. Финал
Сессии 1: приложение запускается, юзер по роли попадает на свой dashboard, навигация по
заглушкам работает. Соответствие ТЗ §6.2–6.5, §14.

## Действия

1. **Адаптивная оболочка** `AppShell` поверх `ResponsiveBuilder` (шаг 5):
   - desktop/web → `NavigationRail`/боковое меню (ТЗ §6.2);
   - mobile → `NavigationBar` (нижняя навигация);
   - реализовать через `StatefulShellRoute` go_router — сохранение состояния вкладок.
2. **Навигационные деревья по ролям** под корневыми маршрутами шага 8
   (`/admin`, `/teacher`, `/student`): каждый — свой набор вкладок/разделов (см. ниже).
3. **Экраны-заглушки** всех разделов из ТЗ §6.3–6.5 и §14: единый `PlaceholderScreen`
   (заголовок раздела + пометка «в разработке»), чтобы каркас навигации был полным.
4. **Три dashboard'а** (`AdminDashboard`, `TeacherDashboard`, `StudentDashboard`) — структура
   будущих блоков (карточки-секции из ТЗ §5.3.6 / §5.4.1 / §5.6.1) с пустыми состояниями
   (`AppEmptyView` из шага 5), без данных.
5. **Общие разделы для всех ролей**: Профиль, Уведомления, Настройки (ТЗ §6.2) — заглушки +
   рабочий `signOut` (шаг 7) и переключатель темы (шаг 5) в Настройках/профиле.
6. **Связать с редиректом (шаг 8)**: корневой маршрут роли открывает её dashboard;
   `requireRole` защищает разделы.
7. **Адаптивная проверка**: прогнать на узком (mobile) и широком (web) экранах, убедиться в
   переключении sidebar ↔ bottom nav и отсутствии переполнений.

## Разделы по ролям (ТЗ §6.3–6.5)

| Роль | Разделы навигации |
|------|-------------------|
| **Админ** (`/admin`) | Dashboard, Пользователи, Преподаватели, Студенты, Группы, Курсы, Статистика, Журнал действий, Настройки системы |
| **Преподаватель** (`/teacher`) | Dashboard, Мои курсы, Мои группы, Банк вопросов, Квизы, Задания, Оценки, Статистика, Импорт/Экспорт вопросов, Профиль |
| **Студент** (`/student`) | Dashboard, Мои курсы, Мои задания, Мои квизы, Мои оценки, Моя статистика, Уведомления, Профиль |

> Все разделы пока — `PlaceholderScreen`. Реальное наполнение — Сессия 2 (по сущностям
> сверху вниз).

## Решения

- **`StatefulShellRoute` (go_router)** — каждая вкладка держит свой стек/состояние; стандарт
  для bottom-nav/rail приложений.
- **Один `AppShell` с адаптивной отрисовкой** (rail vs bar) вместо двух разных оболочек —
  меньше дублирования, единое поведение (ТЗ §6.1 адаптивность).
- **Раздельные деревья на роль**, а не один список с фильтрацией пунктов — чище разграничение
  и проще guard'ы (шаг 8).
- **Заглушки уже сейчас по всем разделам ТЗ** — каркас навигации полный, в Сессии 2 экраны
  заменяются «изнутри» без переделки навигации.
- **Dashboard'ы — со структурой секций**, чтобы в Сессии 2 наполнять данными, а не
  перерисовывать раскладку.

## Артефакты

`shared/navigation/app_shell.dart` (+ конфиг разделов на роль),
`routing/app_router.dart` (StatefulShellRoute для admin/teacher/student),
`shared/widgets/placeholder_screen.dart`,
`features/dashboard/presentation/{admin,teacher,student}_dashboard.dart`,
заглушки общих разделов (профиль/уведомления/настройки) с рабочими signOut и сменой темы.

## Готово, когда

Приложение запускается на web и mobile; после входа пользователь по роли попадает на свой
dashboard; навигация по всем разделам (заглушки) работает; sidebar на web и bottom nav на
mobile переключаются по ширине экрана; выход и смена темы работают; `flutter analyze` чисто.
**Это закрывает Сессию 1** — фундамент готов к наполнению фичами в Сессии 2.
