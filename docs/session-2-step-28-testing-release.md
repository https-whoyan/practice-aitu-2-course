3. **Интеграционные сценарии** (ТЗ §16.3): основные пользовательские сценарии §17 — создание

   через `integration_test` на эмуляторах (шаг 3).
4. **Авторизация и роли** (ТЗ §16.4–16.5): вход/редирект по ролям (шаги 7–8), guard'ы разделов

6. **Импорт вопросов и квизы** (ТЗ §16.7–16.9): предпросмотр/валидация TXT (шаг 21),

7. **Ручное тестирование платформ** (ТЗ §16.10–16.12, §1.2): web, Android, iOS — ключевые
   сценарии вручную; iOS требует Mac + Apple Developer (риск №5 в [`plan-overview.md`](plan-overview.md)).
8. **Адаптивность** (ТЗ §16.13): проверка sidebar↔bottom nav и раскладок на узких/широких

9. **Слабый интернет / offline** (ТЗ §16.14, §11): просмотр кэшированных курсов/материалов/

10. **Ошибки загрузки файлов** (ТЗ §16.15): превышение размера, недопустимый тип, обрыв сети —
    корректные сообщения через `Failure`/UI-кит; согласовано со Storage Rules (шаг 27).
11. **Фиксы**: исправление найденных дефектов, повторный прогон затронутых тестов.
12. **Индексы Firestore** (ТЗ §10): финализировать `firestore.indexes.json` под запросы

13. **Релизные сборки** (ТЗ §1.2, Firebase Hosting): web → `flutter build web` → деплой на

|-----|-------|-----------|

| Widget ключевых компонентов (§16.2) | UI-кит, формы заданий/оценок, квиз, статистика | `flutter test` (widget) |
| Интеграционные сценарии (§16.3) | сценарии §17 на эмуляторах | `integration_test` + эмуляторы |
| Авторизация (§16.4) | вход/восстановление/подтверждение email | widget + integration |
| Роли доступа (§16.5) | редирект и guard'ы по ролям | routing/redirect-тесты |
| Firestore Security Rules (§16.6) | per-collection правила + Storage | `@firebase/rules-unit-testing` (эмулятор) |
| Импорт вопросов (§16.7) | предпросмотр, валидация TXT, пропуск/отмена | unit + widget |
| Прохождение квизов (§16.8) | snapshot, лимит попыток, дедлайн | integration + правила |
| Выставление оценок (§16.9) | оценки/комментарии/возврат, журнал | integration |
| web (§16.10) | ключевые сценарии вручную | ручное (Chrome) |
| Android (§16.11) | ключевые сценарии вручную | ручное (эмулятор/устройство) |
| iOS (§16.12) | ключевые сценарии вручную | ручное (Mac + Apple Developer, риск №5) |
| Адаптивность (§16.13) | rail↔bar, раскладки | ручное на разных ширинах |
| Слабый интернет / offline (§16.14, §11) | кэш курсов/оценок/дедлайнов, черновик, блокировка критичных действий | ручное (throttling) + unit |
| Ошибки загрузки файлов (§16.15) | размер/тип/обрыв | ручное + widget |

## Решения

- **Пирамида тестов**: много unit бизнес-логики, точечные widget, узкий набор интеграционных
  сценариев §17 — быстрый прогон, покрытие критичной логики; согласуется с тем, что считается
  на сервере (шаги 24–25).
- **Тесты правил на эмуляторе как обязательный гейт** (§16.6) — главная граница безопасности
  (шаг 27), без неё релиз не выпускается.
- **Offline по §11 — ручная проверка с throttling + черновики** — Firestore-кэш покрывает
  чтение, критичные действия явно блокируются при отсутствии сети.
- **Индексы финализируем здесь** (§10) — после того как известны все запросы списков/
  статистики; деплой индексов до релиза, чтобы избежать ошибок в проде.
- **Flavor'ы staging/prod для релиза** (шаг 1) — staging для приёмки на облаке, prod для
  публикации; `useEmulators=false` вне dev.
- **iOS — отдельный риск** (риск №5): требует Mac и Apple Developer; при недоступности web и
  Android остаются основными целями релиза §1.2.
