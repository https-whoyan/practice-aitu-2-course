## Цель

Преподаватель проверяет отправки (шаг 18): выставляет оценку с комментарием, возвращает на
доработку, принимает/не принимает, скачивает файлы. Оценки собираются в журнал с фильтрами по
группе/курсу/неделе/заданию/студенту и выгружаются в CSV/JSON. Студент видит только свои
оценки; изменения оценок журналируются в `auditLogs`. Соответствие ТЗ §5.4.6, §5.4.7, §7.9,
§8.6, §12, §13.

## Действия

1. **Фича `grading`**: создать `lib/features/grading/{domain,data,presentation}/` поверх
   `firestoreProvider` (шаг 4).
2. **freezed-модель `Grade`** (шаг 4) ← коллекция `grades` (ТЗ §7.9): `gradeId`, `studentId`,
   `teacherId`, `courseId`, `groupId`, `sourceType`, `sourceId`, `score`, `maxScore`,
   `percentage`, `comment`, `createdAt`, `updatedAt`, `history`; `fromJson/toJson` + конвертеры
   `Timestamp ↔ DateTime` (шаг 4).
3. **Enum `GradeSourceType`** со строковыми кодами (ТЗ §5.4.7): `assignment`, `quiz`, `manual`
   (ручная оценка); `sourceId` ссылается на задание/квиз (для `manual` — пусто).
4. **Модель `GradeHistoryEntry`** (ТЗ §5.4.7 п.11) — запись истории изменения: `score`,
   `comment`, `changedBy`, `changedAt`; хранится в массиве `history`.
5. **Контракт `GradeRepository`** в `domain/`: `watchGrade(id)`, `gradeSubmission(...)`,
   `updateGrade(...)`, `addManualGrade(...)`, `watchGradesForStudent(studentId)`,
   `queryGradebook(filter)` (фильтры §12), `exportGradebook(filter, format)` (§13).
6. **Реализация `FirestoreGradeRepository`** в `data/`: `withConverter`, `percentage`
   вычисляется как `score / maxScore`, ошибки → `Failure` (шаг 4); `@riverpod`-провайдеры.
7. **Экран проверки задания** (UI-кит шага 5): показать отправку (шаг 18), скачать файлы из
   Storage, выставить `score`+`comment`, кнопки «вернуть на доработку» / «принять» /
   «не принять»; запись синхронизирует статус отправки (шаг 18) и создаёт/обновляет `Grade`.
8. **Журнал оценок** (ТЗ §8.6, §14.3): таблица оценок с фильтрами по группе/курсу/неделе/
   заданию/студенту (ТЗ §12) и поиском; преподаватель видит только свои курсы и группы.
9. **Экспорт журнала** (ТЗ §13): выгрузка CSV (журнал оценок группы) и JSON (техническая) —
   формирование на клиенте либо Cloud Function (шаг 10) для больших выборок.
10. **История изменения оценки** (ТЗ §5.4.7): при каждом `updateGrade` добавлять
    `GradeHistoryEntry` в `history` (кто, когда, прежнее значение).
11. **Видимость по ролям** (ТЗ §5.4.7): студент читает только свои `grades`; преподаватель —
    по своим курсам/группам; админ — все (Security Rules, шаг 27).
12. **Журналирование (ТЗ §8.6)**: при создании/изменении оценки писать запись в `auditLogs`
    (через Cloud Function/triggers, шаг 10) — для разбора спорных ситуаций.

## Модель данных (ТЗ §7.9)

| Коллекция | Документ | Ключевые поля |
|-----------|----------|---------------|
| `grades` | `Grade` | `gradeId, studentId, teacherId, courseId, groupId, sourceType, sourceId, score, maxScore, percentage, comment, createdAt, updatedAt, history` |
| `auditLogs` | запись аудита | действие, `actorId`, `target` (`gradeId`), прежнее/новое значение, `timestamp` (ТЗ §8.6) |

**`GradeSourceType` (ТЗ §5.4.7):** `assignment` (оценка за задание) · `quiz` (оценка за квиз,
шаг 24) · `manual` (ручная оценка преподавателя).

**`history` — массив `GradeHistoryEntry`:** `score`, `comment`, `changedBy`, `changedAt` —
полная история изменения оценки (ТЗ §5.4.7 п.4, п.11).

## Решения

- **Единая коллекция `grades` с `sourceType`** (задание/квиз/ручная) — журнал оценок и
  статистика (шаг 25) читают один источник, а не три (ТЗ §5.4.7 пп.5–7).
- **`percentage` денормализуется** при записи (`score/maxScore`) — нужен для журнала и
  агрегатов без пересчёта на каждый запрос.
- **История в массиве `history` внутри документа** — компактно для разбора спорных ситуаций
  (ТЗ §5.4.7 п.11); критичные изменения дополнительно идут в `auditLogs` (§8.6).
- **Выставление оценки — критичное действие (§11)**: пишется только онлайн; запись в
  `auditLogs` выполняет сервер (Cloud Function/триггер, шаг 10), а не клиент (§8.1).
- **Возврат/принятие меняют статус отправки** (шаг 18) транзакционно вместе с `Grade`/
  `teacherComment`, чтобы журнал и статус студента не расходились.
- **Экспорт CSV/JSON** (ТЗ §13): CSV для журнала группы, JSON для технической выгрузки; XLSX —
  отдельный этап (вне MVP).

## Готово, когда

`Grade` сериализуется/десериализуется из Firestore (проверено на эмуляторе); преподаватель
выставляет/правит оценку с комментарием, возвращает на доработку и принимает — статус отправки
(шаг 18) синхронизируется; журнал фильтруется по группе/курсу/неделе/заданию/студенту и
выгружается в CSV/JSON; `history` накапливает изменения, критичные правки попадают в
`auditLogs`; студент видит только свои оценки, преподаватель — только свои курсы; `dart analyze`
чисто, unit-тесты и тесты Rules на эмуляторе зелёные.
