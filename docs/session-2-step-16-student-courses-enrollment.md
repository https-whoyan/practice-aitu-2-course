## Цель

Студент видит свои курсы, вступает в группу по коду приглашения и просматривает структуру
курса (недели, материалы) с учётом видимости: скрытые недели и неопубликованные материалы ему
недоступны. YouTube-видео смотрится внутри приложения. Используются репозитории шагов 13–15 под
student-shell'ом навигации (шаг 9). Соответствие ТЗ §5.6.2, §5.6.3, §8.3, §14.4.

## Действия

1. **Список курсов студента** — по `groupIds`/`courseIds` профиля (шаг 6) через
   `watchCoursesByGroups` (шаг 13); карточки активных курсов, пустое состояние `AppEmptyView`
   (шаг 5). Заменяет заглушку раздела (шаг 9).
2. **Вступление в группу по коду приглашения** (ТЗ §5.6.2) — экран ввода кода; проверка кода
   **Cloud Function** (отметить §9.4–9.5: срок действия, привязка к группе, защита от перебора),
   модель `inviteCodes` (коллекция из ТЗ §7); при успехе студент добавляется в `studentIds`
   группы и получает доступ к её курсам.
3. **Просмотр курса/недель/материалов** — страница курса (описание, преподаватель, недели),
   страница недели (материалы по `orderIndex`); фильтрация видимости: **скрытые недели
   (`isPublished == false`) и неопубликованные материалы НЕ видны** — реальный запрет правилами
   (шаг 27), на клиенте дублируется фильтр (ТЗ §5.6.3, §8.3 п.6).
4. **Просмотр материала** — рендер по `MaterialType` (шаг 15): текст, переход по ссылке,
   открытие файла/PDF/изображения по `fileUrl`, **YouTube-плеер внутри приложения**
   (`youtube_player_flutter`, шаг 15) — без выхода из приложения (ТЗ §5.4.5 п.4–5).
5. **Проверка принадлежности к группе** перед доступом к курсу (ТЗ §8.3 п.8) — на сервере
   (правила/Function); клиент не показывает чужие курсы.
6. **Riverpod-провайдеры/контроллеры** (`@riverpod`, шаг 4) поверх репозиториев шагов 13–15;
   ошибки → `Failure` → `AppErrorView` (шаг 5).

## Экраны (ТЗ §14.4)

| Маршрут | Экран | Назначение |
|---------|-------|------------|
| `/student/courses` | Мои курсы | Активные курсы студента по группам/курсам профиля |
| `/student/join` | Вступление в группу | Ввод кода приглашения (проверка Cloud Function) |
| `/student/courses/:id` | Страница курса | Описание, преподаватель, список видимых недель |
| `/student/courses/:id/weeks/:weekId` | Страница недели | Опубликованные материалы недели |
| `/student/courses/:id/materials/:materialId` | Просмотр материала | Рендер по типу материала |
| `/student/courses/:id/materials/:materialId/video` | Просмотр YouTube-видео | Встроенный плеер |

> Маршруты — под student-`StatefulShellRoute` (шаг 9); заглушки раздела «Мои курсы»
> заменяются этими экранами без переделки навигации.

## Решения

- **Курсы студента — по `groupIds`/`courseIds` профиля** (шаг 6), а не отдельный список —
  один источник принадлежности; доступ дополнительно ограничен правилами (ТЗ §8.3 п.8).
- **Проверка кода приглашения — Cloud Function**, не клиент: срок действия, привязка к группе,
  защита от многократного неверного ввода (ТЗ §5.6.2, §9.4–9.5) — критичное на сервере (§8.1).
- **Двойная фильтрация видимости** — Security Rules как реальная граница (шаг 27) + клиентский
  фильтр для UX; студент не видит скрытые недели и неопубликованные материалы (ТЗ §5.6.3).
- **YouTube внутри приложения** (`youtube_player_flutter`, шаг 15) — единый плеер с
  преподавательской стороной (ТЗ §5.4.5).
- **Общие репозитории шагов 13–15** — студент и преподаватель ходят через один контракт,
  различие только в правах (правила/Function).

## Готово, когда

Студент видит только свои курсы; вступает в группу по валидному коду (Cloud Function), неверный/
просроченный код отклоняется; открывает курс и недели, видит только опубликованное (скрытые
недели и неопубликованные материалы недоступны — проверено на эмуляторе с правилами шага 27);
YouTube-видео проигрывается внутри приложения; `dart analyze` чисто.
