## Цель

При завершении попытки **Cloud Function** сверяет ответы студента с правильными **на сервере**
(клиент правильных ответов не получает — §8.5 п.1), считает балл с учётом режима оценивания
(полный/частичный, §5.5.4), пишет `score`/`maxScore`/`percentage` в `quizAttempts` и создаёт
запись `Grade` (шаг 19, `sourceType: quiz`). Результат раскрывается студенту по `showResultMode`
(шаг 22, §5.5.17). Дедлайн и лимит попыток проверяются на сервере (§8.5 пп.2,7). Это серверная
авторитетная точка оценивания квизов. Соответствие ТЗ §9 (функция «Расчёт результатов квиза»),
§8.5, §5.5.4, §5.5.17.

## Действия

1. **Cloud Function `calculateQuizResult`** (`functions/src/quizzes/calculate.ts`) — триггер на
   завершении попытки. Вариант реализации: Firestore-триггер `onUpdate` `quizAttempts` при
   переходе `status: inProgress → submitted` **либо** callable, вызываемая из `submitAttempt`
   (шаг 23). Каркас функций — [шаг 10](session-2-step-10-cloud-functions-admin.md).
2. **Серверные проверки перед расчётом** (§8.5): попытка принадлежит вызывающему студенту;
   `status == submitted` и ещё не оценена (идемпотентность); `finishedAt ≤ deadline`
   (просрочка — по политике: либо `expired`, либо штраф вне MVP, §8.5 п.7);
   `attemptNumber ≤ attemptsAllowed` (§8.5 п.2).
3. **Загрузка эталонных ответов на сервере**: по `questionSnapshot` (шаг 23) функция читает
   правильные ответы из `questionBank` (шаг 20) — **с учётом перемешивания вариантов**,
   зафиксированного в снапшоте, чтобы индексы совпадали. Клиент в этом не участвует.
4. **Сверка по типам** (4 MVP-типа): `single` — точное совпадение; `trueFalse` — bool;
   `multiple` — полный балл при точном совпадении множеств, либо **частичный** балл за каждый
   верный вариант, если преподаватель включил режим (§5.5.4); `shortText` — совпадение с одним из
   допустимых ответов (с учётом/без учёта регистра, §5.5.9). Типы вне MVP помечаются «требует
   ручной проверки» и не начисляют авто-балл.
5. **Подсчёт итога**: `score = Σ` начисленных баллов, `maxScore = Σ points` снапшота (для
   рандомных квизов — фактический максимум данной попытки), `percentage = score / maxScore`.
6. **Запись результата**: транзакцией обновить `quizAttempts` (`score`, `maxScore`,
   `percentage`, `status: graded`) и создать `Grade` (шаг 19): `sourceType: quiz`,
   `sourceId: quizId`, `studentId`, `courseId`, `score`, `maxScore`, `percentage`, `gradedAt`,
   `auto: true`. Подтягивается в журнал оценок и статистику ([шаг 25](session-2-step-25-statistics.md)).
7. **Раскрытие результата по `showResultMode`** (§5.5.17 пп.9–11, шаг 22): `none` — ничего;
   `scoreOnly` — балл/процент; `scoreAndAnswers` — плюс правильные ответы; `scoreAnswersExplanations`
   — плюс объяснения. Правильные ответы/объяснения **добавляются в попытку только после расчёта**
   и только в разрешённом режиме (§8.5 п.1) — раскрытие контролирует сервер, не клиент.
8. **Запись в `auditLogs`** при необходимости (изменение результата/перерасчёт, §8.6).
9. **Тесты на эмуляторе:** корректность баллов по 4 типам (включая частичный §5.5.4),
   `maxScore`/`percentage`, создание `Grade` с `sourceType: quiz`, отклонение просрочки/превышения
   лимита, идемпотентность (повторный триггер не задваивает оценку), отсутствие правильных
   ответов в попытке при `showResultMode: none/scoreOnly`.

## Cloud Functions

| Функция | Назначение | Серверные проверки |
|---------|------------|--------------------|
| `calculateQuizResult` | Сверка ответов с эталоном из `questionBank`, расчёт `score`/`maxScore`/`percentage`, запись в `quizAttempts` + создание `Grade` (`sourceType: quiz`), раскрытие по `showResultMode` | Принадлежность попытки студенту; `status == submitted` и не оценена (идемпотентность); дедлайн `finishedAt ≤ deadline` (§8.5 п.7); лимит `attemptNumber ≤ attemptsAllowed` (§8.5 п.2); правильные ответы только на сервере (§8.5 п.1); раскрытие строго по `showResultMode` |

> Эта функция — единственное место, где сходятся ответы студента и правильные ответы. Клиент
> отправляет только `answers` (шаг 23); сверка, начисление и раскрытие — на сервере (§8.1, §8.5).

## Решения

- **Расчёт только на сервере** (§8.1, §8.5 п.1): правильные ответы никогда не покидают сервер;
  клиент не может ни увидеть их заранее, ни подделать балл.
- **Эталон берётся через снапшот → `questionBank` с учётом перемешивания** (шаг 23): индексы
  вариантов в `answers` соответствуют перемешанному снапшоту, поэтому сверка идёт по нему, а не по
  «сырому» порядку банка.
- **Частичный балл — опция преподавателя** (§5.5.4): по умолчанию полный балл только за полностью
  верный `multiple`; частичное начисление включается настройкой вопроса/квиза.
- **Идемпотентность расчёта** (`status: graded` + проверка «не оценена») — Firestore-триггер
  может сработать повторно; защита от двойного начисления и дублей `Grade`.
- **Квиз создаёт `Grade` так же, как задание** (шаг 19, `sourceType: quiz`) — единый журнал
  оценок и статистика (шаг 25) без отдельной ветки для квизов.
- **Раскрытие результата — на сервере по `showResultMode`** (§5.5.17): правильные ответы/
  объяснения дописываются в попытку только в разрешённом режиме и только после расчёта.
- **Просрочка/штрафы за дедлайн — вне MVP**: фиксируем проверку дедлайна (§8.5 п.7), сложные
  политики штрафов откладываем (MVP-приоритет из `session-2-features.md`).

## Артефакты

`functions/src/quizzes/calculate.ts` (`calculateQuizResult`),
`functions/src/quizzes/scoring/` (сверка по типам, частичный балл §5.5.4, расчёт `percentage`),
`functions/src/quizzes/grade_writer.ts` (создание `Grade`, `sourceType: quiz`);
обновления моделей `QuizAttempt`/`Grade` (поля результата) в
`features/quizzes/domain/` и `features/grades/domain/` (шаг 19);
`functions/test/calculate_result.test.ts` (баллы по типам, частичный, идемпотентность,
дедлайн/лимит, раскрытие по `showResultMode`).

## Готово, когда

Завершение попытки запускает `calculateQuizResult`; балл считается корректно по 4 MVP-типам
(включая частичный §5.5.4); `score`/`maxScore`/`percentage` пишутся в `quizAttempts`, создаётся
`Grade` с `sourceType: quiz` (виден в журнале и статистике шага 25); правильные ответы не
покидают сервер и раскрываются строго по `showResultMode`; просрочка и превышение лимита
отклоняются; повторный триггер не задваивает оценку; тесты функции на эмуляторе зелёные,
`dart analyze` чисто.
