Работа Сессии 1 («Фундамент», ~35% проекта) разбита на три ветки — по человеку.
Деление **3 / 3 / 6** шагов (поровну по объёму кода):

| Ветка       | Владелец  | Шаги Сессии 1                        | Тема                                  |
|-------------|-----------|--------------------------------------|---------------------------------------|
| `yan`       | Yan       | step 1–3                             | Инициализация, Firebase, эмуляторы    |
| `beksultan` | Beksultan | step 4–6                             | Каркас стека/DI, тема и UI, модели    |

## Как устроены ветки (стопка)

Ветки сделаны **стопкой**: каждая следующая ответвляется от предыдущей и включает
её коммиты. Это сделано намеренно — код шагов зависит друг от друга
(один и тот же `lib/routing/app_router.dart`, `pubspec.yaml` и т.д. правятся
на нескольких шагах), и стопка гарантирует, что при заливке всех веток
**в одну ветку Prct_46 каждая встаёт fast-forward, без конфликтов**.

⚠️ **Стопку нельзя ломать.** Не делать `rebase`/`squash`/`amend` и не мерджить
посторонние ветки в свою — иначе `beksultan` перестанет быть прямым потомком
`yan` (а `duran` — потомком `beksultan`), и fast-forward в Prct_46 сломается.

```
4af1764  (база: ТЗ + план разработки)
   │
   ├── yan          = база + step 1–3
   │     │
   │     └── beksultan  = yan + step 4–6           (содержит коммиты yan)
   │           │
   │           └── duran    = beksultan + step 7–9 + тесты   (содержит yan + beksultan)
   │
   └── common       полная история (код + документация) — рабочая ветка-источник
```

Поэтому заливать в Prct_46 строго по очереди: **yan → beksultan → duran**.
Каждый пуш в `main` Prct_46 — fast-forward, конфликтов нет.

### Что лежит на каждой ветке (коммиты от базы)

**`yan`** (3 коммита):
```
step 1 — инициализация проекта
step 2 — подключение Firebase
step 3 — Firebase Emulator Suite
```

**`beksultan`** (= yan + 3 коммита):
```
… (3 коммита ветки yan) …
step 4 — каркас стека и DI
step 5 — тема и базовые UI-компоненты
step 6 — модель пользователя и данных
```

**`duran`** (= beksultan + 4 коммита):
```
… (6 коммитов ветки beksultan) …
step 7 — авторизация
step 8 — роли и редирект + Security Rules
test  — идемпотентность тестов Security Rules
step 9 — скелет навигации и dashboard'ы
```

> Код на трёх ветках **идентичен** ветке `common`, за вычетом чисто-документационных
> коммитов (их на `common` отдельно). То есть `duran` = весь код Сессии 1 без `docs/`.

## Как всё собирается в Prct_46

Каждый берёт свою ветку из репозитория-источника и заливает её в **одну ветку**
(`main`) репозитория `Tduyer/Prct_46`. Так как ветки — стопка, пуши идут
fast-forward и просто наращивают `main`:

```
Prct_46 / main:
  (пусто)
   └─ Yan пушит  yan       →  main = step 1–3
        └─ Beksultan пушит beksultan →  main = step 1–6   (FF поверх yan)
             └─ Duran пушит duran    →  main = step 1–9 + тесты  (FF поверх beksultan)
```

Порядок **обязателен**: `yan → beksultan → duran`. Если нарушить порядок,
пуш будет non-fast-forward и не пройдёт (придётся ловить конфликты).

Пошаговые команды для каждого — в персональных файлах:
[`teammate-yan.md`](teammate-yan.md) ·
[`teammate-beksultan.md`](teammate-beksultan.md) ·
[`teammate-duran.md`](teammate-duran.md).

Запуск проекта локально (эмуляторы, приложение, тесты): [`dev-runbook.md`](dev-runbook.md).
