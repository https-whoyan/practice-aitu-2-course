## Цель

Студент открывает доступный квиз, видит инструкцию/количество вопросов/лимит времени, начинает
попытку и отвечает на вопросы (ТЗ §5.5.17). Старт попытки выполняет **Cloud Function**: она
формирует снапшот выданных вопросов **без правильных ответов** (§8.5 п.1, п.5), фиксирует время
начала, проверяет лимит попыток и доступность квиза. UI поддерживает таймер, навигацию между
вопросами и восстановление активной попытки после перезапуска (§11). Завершение попытки запускает
серверный расчёт баллов ([шаг 24](session-2-step-24-quiz-scoring.md)). Соответствие ТЗ §5.5.17,
§7.12, §8.5, §11.

## Действия

1. **freezed-модель `QuizAttempt`** ← коллекция `quizAttempts` (ТЗ §7.12): `attemptId`,
   `quizId`, `studentId`, `courseId`, `questionSnapshot`, `answers`, `startedAt`, `finishedAt`,
   `score`, `maxScore`, `percentage`, `status`, `attemptNumber` (см. «Модель данных»).
2. **Enum `AttemptStatus { inProgress, submitted, graded, expired }`** — строковые коды;
   `inProgress` ищется при восстановлении (§11), `submitted` → триггер расчёта (шаг 24).
3. **`QuestionSnapshotItem`** (freezed): `questionId`, `text`, `type`, `options` (с уже
   применённым перемешиванием §5.5.15), `points` — **без `correctAnswer`/`pairs`/`orderItems`**.
   Снапшот хранит вопросы на момент прохождения, чтобы правка вопроса преподавателем не меняла
   завершённую попытку (ТЗ §7.12, §8.5 п.5).
4. **Cloud Function `startQuizAttempt`** (`functions/src/quizzes/start.ts`, callable; каркас —
   [шаг 10](session-2-step-10-cloud-functions-admin.md)): проверяет роль студента и доступность
   квиза (`isPublished`, `startDate ≤ now < deadline`, §8.5 п.8), считает использованные попытки
   и сверяет с `attemptsAllowed` (§8.5 п.2), выполняет выборку вопросов по
   `questionIds`/`randomizerSettings`/`categorySettings` (шаг 22), **вычищает правильные ответы**,
   применяет перемешивание (§5.5.15), создаёт документ `quizAttempts` со `status: inProgress` и
   `startedAt = serverTimestamp()` (§8.5 п.3), возвращает снапшот клиенту.
5. **Контракт `QuizAttemptRepository`** в `domain/`: `startAttempt(quizId)` (вызов функции),
   `watchActiveAttempt(quizId, studentId)`, `saveAnswers(attemptId, answers)` (промежуточное
   сохранение прогресса), `submitAttempt(attemptId)` (перевод в `submitted` → шаг 24),
   `watchAttempts(quizId, studentId)` (история, §5.5.17 п.12). Реализация в `data/` поверх
   `firestoreProvider`/`functionsProvider` (шаг 2/10), ошибки → `Failure` (шаг 4).
6. **Экран «карточка квиза перед стартом»** (§5.5.17 пп.2–5): инструкция, число вопросов, лимит
   времени, оставшиеся попытки, кнопка «Начать».
7. **Экран прохождения** (UI-кит шага 5): рендер вопроса по `type` для 4 MVP-типов (single —
   radio, multiple — checkbox, trueFalse — две кнопки, shortText — поле ввода); навигация
   «вперёд/назад» (если разрешена, §5.5.17 п.7); индикатор прогресса; промежуточное сохранение
   `answers` в `quizAttempts` (для §11).
8. **Таймер** по `timeLimitMinutes` (шаг 22): отсчёт от `startedAt`; по истечении — авто-сабмит.
   **Источник истины по времени — сервер**: дедлайн и лимит проверяются на сервере при сабмите
   (§8.5 п.7, шаг 24), клиентский таймер — только UX.
9. **Восстановление попытки (§11):** при заходе в квиз `watchActiveAttempt` ищет
   `status: inProgress`; если есть и не нарушает настройки (не истёк лимит времени/дедлайн) —
   студент продолжает с сохранёнными `answers`; иначе попытка помечается `expired`.
10. **Завершение** (§5.5.17 п.8): `submitAttempt` → `status: submitted`, `finishedAt`;
    дальнейший расчёт `score`/`percentage` и раскрытие результата — на сервере (шаг 24). Показ
    результата/правильных ответов/объяснений — по `showResultMode` (шаг 22) после расчёта.
11. **Тесты на эмуляторе:** `startQuizAttempt` не кладёт правильные ответы в снапшот; превышение
    лимита попыток и заход после дедлайна отклоняются сервером; восстановление `inProgress`
    возвращает сохранённые ответы; авто-сабмит по таймеру переводит в `submitted`.

## Модель данных (ТЗ §7.12)

| Коллекция | Документ | Ключевые поля |
|-----------|----------|---------------|
| `quizAttempts` | `QuizAttempt` | `attemptId, quizId, studentId, courseId, questionSnapshot, answers, startedAt, finishedAt, score, maxScore, percentage, status, attemptNumber` |

> `questionSnapshot` хранит выданные вопросы **без правильных ответов**; `answers` — ответы
> студента; `score`/`maxScore`/`percentage` заполняются **на сервере** при завершении (шаг 24).
> Снапшот делает попытку независимой от последующих правок банка (ТЗ §7.12).

## Безопасность квиза (ТЗ §8.5)

1. **Запрет доступа к правильным ответам до завершения** — снапшот формируется на сервере без
   `correctAnswer`; клиент их никогда не получает (§8.5 п.1).
2. **Запрет попыток сверх лимита** — `startQuizAttempt` сверяет с `attemptsAllowed` (§8.5 п.2).
3. **Фиксация времени начала** — `startedAt = serverTimestamp()` (§8.5 п.3).
4. **Фиксация времени завершения** — `finishedAt` ставит сервер при сабмите (§8.5 п.4).
5. **Сохранение снапшота вопросов** — `questionSnapshot` (§8.5 п.5).
6. **Защита ответов после завершения** — Security Rules (шаг 27) запрещают правку `answers` при
   `status != inProgress` (§8.5 п.6).
7. **Проверка дедлайна на сервере** — при сабмите/расчёте (шаг 24, §8.5 п.7).
8. **Проверка доступности квиза студенту** — `isPublished`, окно дат, принадлежность к
   курсу/группе (§8.5 п.8).

## Решения

- **Старт попытки — Cloud Function, а не клиентская запись**: только сервер может выбрать вопросы
  и при этом не отдать правильные ответы (§8.5 п.1); клиентская выборка раскрыла бы ключи.
- **Снапшот без правильных ответов** — даже промежуточные ответы и DOM не содержат ключей;
  проверка — целиком на сервере (шаг 24).
- **Клиентский таймер — только UX, авторитет по времени у сервера** (§8.5 п.7) — расхождение
  часов клиента не даёт обойти дедлайн.
- **Промежуточное сохранение `answers`** в `quizAttempts` — обязательное условие восстановления
  попытки (§11); без него закрытие приложения теряло бы прогресс.
- **Восстановление только если не нарушает настройки** (§11): истёкший лимит/дедлайн → `expired`,
  а не продолжение.
- **MVP — рендер 4 типов** (шаг 20); остальные типы в снапшот не попадают, пока нет их UI.
- **Доступ только через `QuizAttemptRepository`** (эталон шага 4).

## Готово, когда

Студент видит карточку квиза и стартует попытку; `startQuizAttempt` создаёт `quizAttempts` со
снапшотом **без правильных ответов** и серверным `startedAt`; прохождение 4 MVP-типов работает,
ответы промежуточно сохраняются; таймер ведёт отсчёт и авто-сабмитит; перезапуск приложения
восстанавливает активную попытку с сохранёнными ответами (§11); превышение лимита попыток и заход
после дедлайна отклоняются сервером; завершение переводит попытку в `submitted`; `dart analyze`
чисто, тесты функции и моделей на эмуляторе зелёные.
