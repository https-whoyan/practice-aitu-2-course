## 0. Базовый цикл исправления (применять к каждой задаче)

1. **Симптом** — что наблюдается (по ТЗ-пункту).
2. **Корень** — на каком слое проблема: Security Rules / Cloud Function / репозиторий / провайдер / UI / модель.
3. **Фикс** — минимальное изменение на корневом слое.
4. **Проверка** — тест правил в эмуляторе, ручной сценарий, `flutter analyze` (на ASCII-пути!), `npm run build` в `functions/`.
5. **Регрессия** — не сломал ли соседние сценарии (особенно правила доступа).

> Правило слоя: баг про **доступ/целостность** — чинить в Security Rules / CF, не в UI.
> Скрытие кнопки ≠ защита (ТЗ §8.1).

Приоритеты: **P0** безопасность → **P1** подключить готовый бэкенд к UI →
**P2** корректность данных и мелкие недостающие фичи → **P3** заглушки→данные →
**P4** объём MVP→ТЗ → **P5** полировка.
